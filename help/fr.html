Démarrage et exigences

Linux Mint, Python 3.12, GTK 4, PyGObject/Pycairo et Poppler. Matplotlib est requis pour les graphiques et est inclus dans le package installable. Lancez via l'entrée desktop/menu ou python3 -B -m loto45. Fichier → Quitter quitte. Le démarrage crée une base de données vide manquante, vérifie l'intégrité et étend le schéma uniquement après la sauvegarde. Les problèmes affichent un code d'erreur et un remède. config/settings.json sélectionne la base de données active.

Menus et archives

Lotto 6 sur 45 et Joker ont des derniers tirages de loterie distincts, une recherche de date, une recherche de numéros, des cotes, des statistiques et des combinaisons de loterie. Shared contient l'inventaire, les notes de révision, les vérifications de données, les sources, le journal d'importation, les importations locales, la sauvegarde, la restauration et les diagnostics. Les dates affichent leur jour de semaine calculé. La recherche par date accepte DD.MM.YYYY, MM.YYYY, YYYY et la saisie partielle ; Les tirages en semaine et de loterie permettent d'affiner davantage les résultats. Les filtres numériques Lotto prennent uniquement en compte les numéros principaux. Les cotes conservent zéro, les montants inconnus, les ATS/EUR et les jackpots.

Rechercher de nouvelles données

Le bouton ou Fonctions communes → Mettre à jour et vérifier les données utilise la sélection de source enregistrée. Le rapport répertorie les fichiers inchangés, les modifications, les notes et les échecs. La réimportation ne duplique pas les tours. Le jeu, la date et l'identifiant identifient un tour ; les mêmes chiffres peuvent se produire à des jours différents. Les erreurs critiques de l'analyseur annulent le fichier concerné. Des conflits subsistent dans les notes de révision ; La CLI --allow-corrections active explicitement la correction.

Gérer et vérifier les sources

Fonctions communes → Télécharger ouvre la gestion des sources. Modifier le nom, l'URL, le jeu, le format, la priorité et l'activation ; la priorité inférieure est traitée en premier. Les valeurs par défaut sont resources/default_sources.json ; remplacements dans config/download_sources.json. La sélection existante et les URL modifiées sont conservées. Les valeurs par défaut manquantes sont ajoutées désactivées. De nouvelles installations permettent d'accéder aux sources officielles ; les archives tierces restent facultatives et désactivées. Vérifier les sources récupère un échantillon et vérifie la structure de l'analyseur. CSV/PDF doit correspondre aux formats yearly/archive pris en charge, et non à des tableaux arbitraires. Les noms de fichiers annuels incluent l’année.

Fichiers et journaux temporaires

Les téléchargements d'archives et la préparation PDF utilisent leurs propres répertoires /tmp et sont supprimés après la préservation des répertoires verrouillés actifs success/failure. et des fichiers non liés ; les répertoires marqués orphelins sont supprimés au démarrage. Les fichiers bruts rejetés sont conservés de manière permanente dans data/rejected/<sha256>.bin pour le diagnostic. Le journal d'importation de base de données persiste. logs/error.log redémarre à chaque session ; --help et --version le laissent inchangé. Les téléchargements de langues utilisent un sous-répertoire temporaire dans le dossier Téléchargements utilisateur.

Statistiques et graphiques

Choisissez Statistiques dans un menu de jeu. Calendrier start/end (YYYY-MM-DD), jour de la semaine (-1 tous, 0 lundi à 6 dimanche), type de tirage de loterie et dernier N fonctionnent ensemble ; Actualiser applique les entrées. Les filtres de calendrier sont appliqués avant le dernier N. Sélectionnez l'année écoulée à l'aide de From/To.. Lotto inclut les fréquences, les écarts, pairs/triples, les sommes, la parité, les répétitions et les modèles. Des modèles supplémentaires couvrent les nombres premiers, les nombres d'anniversaire, les paires de miroirs, les décennies, les écarts arithmétiques et les quantiles. Les tableaux roulants utilisent jusqu'à 20 tirages de loterie par point. Le score Z est un écart standardisé ; le chi carré est descriptif sans valeur p.

Analyse Joker

Joker conserve les zéros non significatifs et l'ordre des six positions. Les modèles et les distributions incluent les fréquences de position, la somme des chiffres, la parité E/O, les chiffres distinct/repeated, les voisins égaux, la plus longue course, la symétrie (0–3), les palindromes, les transitions, les suffixes, l'entropie de Shannon en bits et les comparaisons en semaine. Les cartes thermiques des jours de semaine contiennent des fréquences absolues et dépendent du nombre de tirages de loterie par jour de semaine. E = pair, O = impair.

Affichage graphique

Matplotlib dessine localement à l'aide des polices et des couleurs du système. Les graphiques indiquent la période, la taille de l’échantillon et les filtres. Les exportations de dessins, de statistiques et de graphiques ne sont pas disponibles. les combinaisons de loterie peuvent être enregistrées sous le nom CSV ou imprimées. Sur X11, l'application est par défaut Le Caire sans DRI3 ; un choix explicite GSK_RENDERER est respecté.

Créer des combinaisons de loterie

Choisissez Créer des combinaisons de loterie dans le menu du jeu et entrez un décompte positif. La limite par défaut est de 10 000 ; Modifier → Paramètres autorise 1 à 1 000 000. Le hasard pur est toujours disponible sans filtres. Le filtrage statistique affiche directement les règles activées individuellement. Définissez les valeurs dans la page de statistiques correspondante sous Configurer les filtres de combinaison de loterie ; La création de combinaisons de loterie ne fournit que des cases à cocher d'activation. Saisissez minimum/maximum séparé par une virgule, par exemple 2,4. Le poids -5 favorise les rares, +5 les fréquents et 0 est neutre. SystemRandom est le générateur aléatoire normal. Chaque combinaison Lotto est triée avec six nombres distincts ; Joker est un texte à six chiffres. Il n'y a aucun doublon dans un lot.

Filtres Lotto

Plage de somme ou quantiles historiques 0 à 100 %, nombres pairs, nombres 1 à 22, tirage consécutif le plus long, répétitions du dernier tirage de loterie sélectionné, plage minimale, nombres premiers, nombres 1 à 31, occupation exacte de la décennie (cinq comptes totalisant 6) et préférence de paire. Sommes de permis inhabituelles<80 ou>= 190, six nombres even/odd ou séries d'au moins quatre. Les pondérations sont des préférences de sélection et non des prédictions.

Filtres Joker

Poids de position, somme 0 à 54, chiffres distincts 1 à 6, séquence adjacente la plus longue, occurrences maximales d'un chiffre n'importe où, palindrome allow/avoid/only et préférence pour les deux derniers chiffres. Les règles historiques exigent des tirages de loterie dans la période sélectionnée. Des règles strictes s'arrêtent après des tentatives limitées avec L012 et des décomptes de rejets.

Profils, historique et impression

Entrez un nom de profil et enregistrez ; load/delete via le formulaire ou le menu Profil. Les profils Lotto et Joker sont distincts. Loading/saving définit le profil CLI sélectionné. Chaque lot stocke un instantané de profil complet indépendant, un horodatage et un mode RNG. L'historique affiche les lots précédents dans des pages. Imprimer ouvre la boîte de dialogue système GTK. l'historique des combinaisons de loterie est conservé. les lots de combinaisons de loterie peuvent être enregistrés sous le nom CSV. Importez les colonnes Joker sous forme de texte dans des feuilles de calcul pour conserver les zéros non significatifs.

Sauvegarde, diagnostic et restauration

Partagé → La base de données de sauvegarde utilise la sauvegarde SQLite et nécessite une nouvelle destination. Vérifier la base de données vérifie l'intégrité et les clés étrangères. Une extension de schéma crée d'abord une sauvegarde automatique dans data/backups/.. Les originaux endommagés ne sont jamais écrasés. La restauration vérifie la source, la copie dans un nouveau fichier et ne l'active qu'après succès. Les diagnostics contiennent la version, le schéma, les vérifications et l'état import/source sans chemins informatiques ni données brutes. Les nouvelles archives ne créent pas des millions d’entrées combinées ; les catalogues existants restent.

Configurer les filtres de combinaison de loterie dans les statistiques

Définissez sums/quantiles dans les sommes, les nombres even/low dans Parity/Low-high, les exécutions dans les voisins, les répétitions dans les répétitions, l'étendue dans les plages, la préférence de paire dans les paires et la pondération dans les nombres. D'autres règles Lotto se trouvent dans les modèles. Pour Joker, la pondération se trouve dans les statistiques Joker et d'autres règles dans les modèles. Ouvrez Configurer les filtres de combinaison de loterie, modifiez les valeurs et enregistrez. La création de combinaisons de loterie n'active que les règles avec des cases à cocher. La période de référence est partagée au sein de chaque jeu et indépendante de la période d'affichage des statistiques. Les valeurs sont stockées sous tip_rule_settings dans config/settings.json. Le chargement d'un profil applique ses valeurs à ces paramètres ; les lots de combinaisons de loterie antérieurs conservent leurs instantanés. La colonne Type est masquée jusqu'à ce que l'intégralité des archives du jeu contienne une valeur autre que le tirage principal de la loterie ; actualisez ou rouvrez la vue pour revérifier.

Codes de sortie : 0 succès, 1 échec d’opération, 2 erreurs d’argument.

Origine et installation

La source complète Python et le bytecode Python 3.12 installable sont livrés séparément. python3 install.py installe les lanceurs de bureau et de menu ; python3 install.py --uninstall supprime les fichiers journalisés inchangés, préserve les données utilisateur ultérieures et signale les fichiers conservés. Voir --help pour --prefix, --desktop-dir et --menu-dir. README.md décrit les exigences et la construction. Licences : LICENSE et THIRD_PARTY.md.

Les paramètres de filtre de combinaison de loterie non valides dans config/settings.json sont signalés comme L004 et ne sont pas remplacés ; vérifiez tip_rule_settings pour le jeu concerné. Les écritures échouées conservent les paramètres précédents.

Les champs de date ont un calendrier adjacent. DD.MM.YYYY, y compris days/months à un chiffre, et YYYY-MM-DD sont acceptés ; les dates sont stockées au format ISO. Les champs vides ne limitent pas la période.

Le basculement entre Lotto et Joker conserve la page de menu actuelle lorsqu'elle est disponible. La création de combinaisons de loterie et l'historique des combinaisons de loterie restent des vues distinctes. Les modèles sont disponibles pour les deux jeux. Les statistiques spécifiques à Lotto passent aux statistiques Joker ; le retour en arrière restaure la dernière page de statistiques Lotto.

Les champs de type de tirage de loterie, comme la colonne Type, ne sont affichés que lorsque les archives du jeu contiennent un autre type. Rouvrez la vue ou actualisez les statistiques après l'importation. Les diagrammes de fréquence mettent automatiquement à l'échelle leurs axes ; 500 n’est pas un plafond. La période Tout inclut chaque tirage de loterie stocké.

Les graphiques de fréquence montrent le nombre maximum réel dans le titre et sur l'axe vertical. Une ligne pointillée marque cette valeur. La modification de la période met à jour à la fois le maximum et l'échelle.

Tous les graphiques affichent le maximum de données analysées dans le titre. Les graphiques à barres et à courbes ajoutent une graduation sur l'axe des valeurs et une ligne de guidage. Les cartes thermiques affichent le maximum sur une échelle de couleurs et décrivent les cellules avec cette valeur. Les lignes de référence sont exclues du maximum de données. Les graphiques vides n'affichent pas de maximum.

L'inventaire utilise des onglets pour Lotto/Joker, les sources et les détails de la table. Les catalogues complets affichent le nombre de combinaisons une fois ; les catalogues incomplets montrent des stocks hors du possible. Les sources de téléchargement et les détails des résultats utilisent Précédent et Suivant sans barres de défilement. Les modifications survivent aux changements de page ; Enregistrer stocke toutes les sources.

Pour les sources win2day et GitHub, le logo original du site Web apparaît à droite, sélectionné par URL. Les fournisseurs inconnus n'affichent aucun logo. Si l'image locale n'est pas lisible (L001), le téléchargement reste disponible ; restaurez l'image correspondante dans resources/site-logos à partir du package d'application.

Fonctions communes → Mettre à jour et vérifier les données combine le téléchargement de nouvelles données, la vérification de l'intégrité de la base de données et la création d'un rapport de diagnostic. Les rapports sont enregistrés automatiquement sous logs/ avec un horodatage ; le résultat montre leur emplacement. Les erreurs individuelles n’empêchent pas les contrôles ultérieurs. Annuler arrête le flux de travail. Pour les erreurs d'écriture (L001), vérifiez les autorisations et l'espace libre dans le dossier des journaux.

Les quatre étapes sont visibles dès le début, chacune avec son propre statut. Les détails du téléchargement en direct apparaissent ci-dessous. Une coche s'affiche uniquement une fois cette étape terminée avec succès ; l'étape de diagnostic nécessite également la sauvegarde du rapport.

Le flux de travail combiné commence par « Vérifier les sources », vérifiant la disponibilité et la structure des données des sources activées. La récupération des données, la validation de la base de données et le rapport de diagnostic suivent. Les quatre étapes ont leur propre ligne d'état. Les échecs de source apparaissent dans le résultat et le rapport ; les contrôles ultérieurs sont toujours en cours.

Le logo de l'application 6 aus 45 apparaît à droite des étapes de contrôle. Si l'image est manquante ou endommagée (L001), les chèques restent disponibles ; restaurez resources/logo-6aus45-v1.png à partir du package d’application.
